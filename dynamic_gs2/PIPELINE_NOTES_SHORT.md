# Sim Pipeline — reproduction notes (condensed)

Short, concept-level companion to `PIPELINE_NOTES.md`. Same Static / Dynamic / Shared structure, every load-bearing hyperparameter kept, but no code identifiers — algorithm + reasoning + numbers only.
Scope: the live-sim full pipeline (Gazebo/ROS sim camera → static capture → dynamic loop).

---

## STATIC PHASE

### Sweep capture, trigger UI & keyframe recording
- One source-agnostic static orchestrator runs a fixed schedule for live capture: prewarm the heavy 3D object generator alone during the sweep, open the camera/depth stream, show a trigger UI, record deduped keyframes (incrementally fusing them into the depth seed as they arrive), and on operator trigger run a shared back end: 2D segment, 3D object generation, free that VRAM, spawn the dynamic-phase models, build the TSDF seed, train the scene, then place/fuse the 3D object. Recorded runs reuse an existing seed and skip the live UI.
- The trigger UI is a minimal web viewer (default port 8081) that just push-streams the live camera image (no Gaussian render yet — there is no scene). It overlays a centered red square (side 500 px on the CLI, 300 default) so the operator frames the object inside it, and a single "Trigger" button (also fires on a bare Enter for headless use). A background thread keeps the feed real-time during everything (sweep + generation + train). A 6-step checklist (capture, segment, generate, train, fuse, realtime) with per-step elapsed timers is the only phase indicator; the red box is dropped once triggered. On a mid-session resolution change it pushes a 1x1 image first to force the browser to re-create the canvas at the new size.
- Keyframe dedup is a greedy ORB-SLAM-style gate (motion mode): frame 0 always kept; a later frame is kept only if it is far enough from EVERY prior kept frame in translation OR rotation — i.e. rejected only when some kept frame is within BOTH 0.02 m (2 cm) translation AND 20 deg rotation (geodesic angle from the rotation matrices). This drops near-duplicate views so training isn't fed redundant frames. An alternate time mode (one frame every 1.0 s, motion-ignored) exists for a fixed real-HW camera.
- Each kept keyframe is written as BGR PNG (rgb), uint16-mm TIFF (depth, NaN/inf zeroed then clipped to [0, 65535]), and uint8 mask, plus a pose entry; the pose entry is staged only after all three files verifiably exist, so the manifest never references a missing file. The manifest is written atomically (temp file + rename) with intrinsics (w, h, fl_x, fl_y, cx, cy) in the header. Poses are OpenGL c2w.
- Two GPU-contention controls protect the shared 16 GB card: the sweep publisher can be Hz-capped (e.g. ~10 Hz) so the concurrent 3D-generator load hides under the sweep; and once the sweep ends an "rgb-only" sentinel tells the publisher to drop its GPU-heavy robot-mask render + depth decode (nothing downstream needs them anymore), freeing the GPU for the seed build + training.
- Fail-fast: if segmentation finds zero objects, the run releases the 2D segmenter and raises a retry error (object must fill the red box, prompt a short matching noun) rather than running generation + fusion + train on an empty set and crashing ~30 s later in the tracker.

### 2D segmentation (FastSAM + CLIP)
- Class-agnostic instance masks come from FastSAM (Ultralytics YOLOv8-seg) in one forward pass, then CLIP (open-clip, ViT-B-32-quickgelu, OpenAI weights — the quickgelu variant is required or match quality silently degrades) scores each mask crop against a single short-noun text prompt. Unlike FastSAM's built-in top-1 text mode, ALL candidate masks are kept with scores so the downstream filters decide. FastSAM-x + CLIP are light enough to co-reside in one persistent worker with the heavy 3D generator.
- The exact trigger frame (RGB + float32-metre depth + intrinsics + pose) is snapshotted into an anchor folder, with the robot blacked out of the RGB (using the keep-mask) so segmentation sees the object, not the gripper. This is the identical frame the 3D generator and world-placement step later consume — no cross-frame resampling.
- FastSAM is run at imgsz=1024, retina_masks on, conf=0.4, iou=0.9 (deliberately low conf / high NMS-iou to keep many candidates and let CLIP do the selecting). Each raw mask is split into 8-connectivity connected components (dropping components below 0.002 of image area) so a single mask spanning two disjoint objects gets separated before CLIP.
- CLIP scoring crops each mask's bbox, whites-out in-bbox background outside the mask, and computes cosine similarity to the prompt; it keeps BOTH a softmax probability (for ranking, logit scale 100) AND the raw cosine (for an absolute presence gate).
- Candidates are first reduced to "survivors": pixel area within [0.002, 0.25] of the image (drop specks and wall/table-sized blobs) AND not touching >=2 image borders (an edge-hugging mask is background).
- Auto-threshold (default) decides HOW MANY to keep via the largest consecutive log-prob gap among survivors: keep up to the biggest gap only if that gap is >= a 2.5x ratio (a real winner->tail jump is large; ratio space is count-invariant). A separate presence gate on raw cosine (robust MAD floor with k=3, the 1.4826 MAD-to-std factor, plus a fixed absolute margin of 0.04 to kill phantoms on homogeneous backgrounds) answers "is anything here at all" and yields the 0-objects fail-fast. The hard score floor is OFF (set to 0.0) on this path; the auto gates own the decision.
- Container promotion: if a kept mask is >=80% contained inside a larger survivor of nearly-equal cosine (within 0.03), swap up to the fuller mask — because component-splitting can score a distinctive sub-part above the whole object. Then largest-first dedup drops any later mask that is >0.6 IoU or >=80% contained in an already-kept one, keeping the fullest. Survivors are truncated to at most 8 objects.
- Output is a per-object list of {mask, score, bbox, area, object_index} plus overlay PNGs and a manifest, all paths relative to the segmentation folder so a copied/renamed dataset never breaks. The prompt selects ONE object family; the gates determine how many instances survive.

### 3D object generation (Fast-SAM3D)
- The 3D generator (Fast-SAM3D) takes the anchor RGB + per-object 2D masks + the anchor's metric depth and intrinsics, and produces one per-object 3D Gaussian splat (in a canonical frame) plus a pose sidecar (translation, rotation wxyz quaternion, scale). World placement is NOT done here — that is the fusion step. Fixed seed 42 for determinism.
- It loads ONCE on demand into a long-lived worker subprocess (heavy import + checkpoint hidden under the operator sweep), communicating one JSON-per-line over a pipe; the worker reserves the protocol stdout FD and routes any stray prints/loguru to stderr so they can't poison the line protocol. The same worker also hosts the 2D segmenter, so calls are inherently serial — which is exactly why VRAM must be scheduled (load each model only when needed, unload promptly).
- The generator is configured to the lightweight gaussian-only path: render engine pytorch3d, float16, depth model on CPU and bypassed when a real pointmap is supplied, decode format = gaussian only (the mesh decoder's 256^3 grid would OOM). A VRAM-trim step halves the diffusion generators and DINOv2 condition embedders to fp16 and parks never-invoked modules on CPU, so it can co-reside with capture/seed/train. Sampler/decoder knobs are fixed (e.g. SLAT decode threshold 0.5, token ratio 0.15).
- When real depth + intrinsics are given, a full-resolution metric pointmap is back-projected and fed in so generation uses true metric depth instead of the model's scale/shift-invariant estimate. The back-projection folds the CV->pytorch3d axis flips (x-left, y-up, z-fwd) and marks z<=0 pixels as holes.
- Per object, an OOM retry ladder shrinks the network's max long-side from 518 down through 112/96/80/64/48 (518 is the normal feed); on each OOM it drops to the next rung until inference succeeds (image bilinear, mask nearest then re-binarized). A failed/skipped object yields a status dict, not an empty result.
- The per-object Gaussian PLY stores color as 0-order spherical harmonics; loading it back decodes SH->RGB (clamped [0,1], grey 0.5 if absent) to get the gaussian-center point cloud the fusion step registers, and reads the wxyz rotation quaternion (validated finite 4-vector) used as the rigid-rotation init for placement.

### TSDF depth seed (point-cloud init)
- The seed is one point cloud written under the static scene that initializes the scene Gaussians (one Gaussian per seed point); the manifest is patched to point the nerfstudio dataparser at it. The world frame is metric and unrecentered (no orientation/center/auto-scale) so the seed lands in the same frame as the recorded camera poses.
- During live capture the seed is built incrementally on a background CPU thread as keyframes arrive (CPU forced so it can't OOM or contend with the concurrent 3D-generator load on the shared GPU), so by trigger time only the final extract+downsample+write remains. Recorded runs (and the fallback if the incremental build fused nothing) run the identical algorithm one-shot in a CPU subprocess (subprocess isolation contains Open3D/CUDA teardown aborts).
- Only deduped keyframes are fused (same 2 cm / 20 deg gate). Per keyframe: NaN-scrub depth, convert to mm; zero out robot/gripper pixels (using the keep-mask) so they enter neither ICP nor TSDF; reverse BGR->RGB for color. Color is fused into the TSDF and becomes the Gaussians' initial color — a colorless/black seed is the documented root cause of opacity-collapse (train drives opacity->0, end-of-train purge culls a large fraction, leaving holes), so the BGR->RGB reversal is load-bearing.
- Per-frame fusion (Open3D): convert OpenGL c2w to OpenCV; build an ICP source cloud by back-projecting only depth in (0.05 m, 2.0 m), strided (stride 8 for the live seed vs 4 default — halves ICP cost, TSDF integrate untouched), voxel-downsampled to 0.01 m (1 cm), normals estimated with radius 0.03 m / max 30 neighbors. Point-to-plane ICP registers this source, FK-pose-initialized, against a global accumulated model.
- ICP runs coarse->fine: stage 1 = 5 cm max-correspondence, 6 iters; stage 2 = 2 cm, 12 iters, chaining the transform. The refinement is accepted only if ICP fitness >= 0.30, else it falls back to the raw FK pose (trust forward kinematics on textureless/empty views) — preventing a bad solve from corrupting the seed.
- The global ICP model stays bounded by scene extent: every 5 frames the pending registered sources are merged in, re-voxel-downsampled to 1 cm, and normals re-estimated.
- TSDF integration uses FULL-resolution depth (not the decimated ICP source) at the refined pose; surfaces beyond the 2.0 m truncation are not integrated (no seed Gaussians past 2 m — this cap should equal the training loss's depth-cap). Seed TSDF voxel = 0.003 m (3 mm), truncation half-width = 0.008 m (8 mm). The 3 mm voxel is mandatory: the 2 mm default yields a denser/taller-bbox seed with far-surface fragments the renderer can't fit; over-large truncation smears the SDF and carves spurious double surfaces.
- The GPU fusion impl (only a fallback here; the seed forces CPU) must set its truncation multiplier explicitly to match the CPU's fixed 8 mm — Open3D's default 8x-voxel multiplier gives 2-3x larger truncation and produces a far-edge "doubling" the CPU path never shows.
- Finalize extracts the full TSDF point cloud, then adaptive-downsamples anchored on the LAST camera position (the operator's final framing of the object): points within 1.0 m of that camera are kept at native density, all farther points voxel-downsampled to 0.01 m (1 cm). Colors and normals are preserved.

### Splatfacto scene training
- The scene is trained in-process (no ns-train subprocess) by driving the gradient render of a wrapped nerfstudio Splatfacto/gsplat model whose Gaussian parameters ARE the shared per-Gaussian buffers (same objects, no copy), so count surgery just re-points the optimizer in place. Keyframes are visited round-robin, deterministically.
- LRs (per the static invariants): means = 0.0, features_dc = 0.0025, features_rest = 1.25e-4, opacities = 0.05, scales = 0.005, quats = 0.001 (Adam, eps 1e-15, no scheduler). The means LR=0 lock is enforced at build AND re-asserted after every count change, so Adam never moves the seed positions even though gradients are nonzero — every Gaussian stays pinned to the geometrically-correct ICP-fused seed; only color, opacity, scale, orientation train. Letting means drift under photometric loss would smear the output.
- Camera-pose optimization is OFF (structurally — the camera-opt group is never created), because the captured poses are already ICP-refined to sub-mm; leaving pose-opt on would drift cameras visibly.
- Training runs in fp32, NOT fp16: the gsplat backward + SSIM lose too much precision under fp16 autocast (measured ~17-18 dB masked PSNR at fp16 vs ~26-27 dB at fp32). The multi-optimizer scaler step is used (not a single scaler.step) because stepping a grad-less optimizer repeatedly corrupts the GradScaler state and silently drops real steps.
- Splatfacto's own densify/clone/split/prune is disabled (a no-refine strategy), so count is changed only by explicit surgery. Because prune never runs, an explicit scale-clamp is needed: every 10 steps (starting at step 60, after the coarse warmup), any Gaussian whose largest world axis exceeds 0.05 m has all three log-scales shifted equally so the largest axis becomes 0.01 m (shape-preserving, removing far-band smear splats).
- Training is 500 steps max with a coarse-to-fine resolution schedule (steps 0-14 at 1/4 res, 15-29 at 1/2, >=30 full res). A photometric early-stop: track an EMA of the loss and stop once it stays below 0.02 for 8 consecutive steps after a 100-step minimum. After the loop the render step is set high so all SH bands are active for the fusion step.
- Loss = 0.8*L1 + 0.2*(1-SSIM) (SSIM data_range 1.0, 3-channel), with GT composited onto the fixed sky background first. A loss mask (multiplied into both GT and prediction) combines the per-frame robot keep-mask AND a depth-cap mask keeping only pixels with sensor depth in the open interval (0.05 m, 2.0 m) — so color is never fit to far/no-return or robot pixels.
- Background color is forced to the Gazebo sky (0.86, 0.92, 1.0) and the override is applied even during training — Splatfacto's default "random" background would otherwise inject a random photometric bias the renderer compensates for at silhouettes via opacity tweaks.
- Seed init: means = seed xyz directly; per-point scales = log of mean distance to 3 nearest neighbors (repeated over 3 axes); quats random unit; opacities = logit(0.1); colors = RGB->SH band 0 (higher bands zeroed). SH degree 3; scene box sized to 4x the seed extent.
- After training, a one-shot opacity purge culls every Gaussian whose activated opacity (sigmoid) is below 0.05 — removing faded floaters the photometric fit drove transparent — before the object-fusion step runs.

### Phase-0b: place & fuse the 3D object into the scene
- This step places each generated 3D object into the trained scene and tags which Gaussians belong to it. The scene buffers use the exact reallocating (non-free-list) path here because the placement indices and instance-id scatter assume STABLE row positions across per-object inserts; a free-list swap-remove would reorder rows and write IDs onto the wrong ones.
- The registration target is the real surface: the object's 2D mask is back-projected through the anchor's metric depth into world points+colors. Depth outliers are scrubbed with a permissive ~7.4-MAD gate (preserve real extent), and a near-surface filter (assuming surfaces no steeper than 70 deg, window ~0.012*min(H,W)) drops silhouette-edge depth that bleeds onto the table. If fewer than 3 target points survive, the object is skipped. (If no anchor depth existed, the fallback target is the frontmost visible trained-Gaussian subset under the mask, keeping one frontmost Gaussian per pixel.)
- Initial placement is a similarity transform: the SAM3D rotation-quaternion pre-orients the canonical cloud (with a pytorch3d->scene-camera axis flip and the camera-to-world rotation), then isotropic scale = target bbox-diagonal / source bbox-diagonal and centroid translation align it. Robust 5-95 percentile / trimmed-mean stats (when >=50 points) are used so back-projected boundary outliers don't blow up the bbox/centroid. Both clouds are then voxel-downsampled at ~3x their median NN spacing for the refinement backend.
- The refinement backend (default = non-rigid "ndp") warps the source onto the target: a deformation pyramid (motion Sim3, depth 3, width 128) fit with per-level Adam (lr 0.01, up to 500 iters/level) on 6000-point subsamples, minimizing symmetric truncated Chamfer plus a regularizer (weight 1.0) that pulls non-rigidity toward rigid on coarse levels; early-stops on small/relative loss change. Alternatives: rigid CPD (color-aware, scale on, w=0.5, 70 iters) and a TEASER++ pipeline (color-aware FPFH + GNC-TLS solve, noise_bound 0.02, then a tighter reproject solve at 0.005, then a guarded point-to-plane ICP polish that only accepts a strictly better inlier count).
- Insert/cull happen against the trained scene so new geometry doesn't stack on or float ahead of the real surface. Stage A drops aligned points whose nearest existing in-mask Gaussian (within a 0.015 m depth tolerance of the front surface) is closer than tau = max(1.3 * local spacing, 0.003 m). Stage B drops aligned points lying in FRONT of the trusted real-depth surface (front-buffer from the back-projected depth, dilated 2 px, band 0.0 m); points with no surface along their ray are kept.
- Surviving points are inserted as new Gaussians: scales = log of mean-3NN spacing per point, colors RGB->SH band 0, identity orientation, opacity = logit(0.1) (0.1 opacity). On insert each gets its instance id (1..K) and an inserted-flag; the object-flag stays 0 (the dynamic phase's first-frame selection sets it later).
- Stage C also tags already-trained scene Gaussians belonging to the object (so the original surface carries the instance id, not just the inserts): in-mask rows at a looser 0.02 m depth tolerance whose instance id is 0 (or already this object's) and that are near the aligned proxy points or the existing subset (radii ~0.003-0.02 m) get the instance id scattered in.
- A guard raises if zero object Gaussians were tagged across all objects ("nothing to track") — otherwise a fully-failed object set would only surface later as an opaque tracker error.
- The whole post-fusion scene (6 Gaussian params + 4 identity buffers, live rows only, on CPU, with a config fingerprint and layout tag) is saved to a warm-cache file; the dynamic phase warm-loads this exact scene with no retrain, and the tracker keys on the Phase-0b instance-id tagging.

### Model loading, workers & VRAM scheduling
- Every heavy model is wrapped behind one uniform async lifecycle — non-blocking prewarm (load on a background thread), wait-ready (block until loaded), release (free VRAM), plus an inference call — so the orchestrator never imports a model directly and load cost overlaps the sweep instead of hitting the critical path. Real load wall-times are recorded only after each background load returns (a timer around the non-blocking prewarm would measure only dispatch).
- The 2D segmenter and 3D generator share ONE persistent worker process (one spawn, one CUDA context, models loaded on demand) so they co-reside; closing that whole process — not just unloading — is what 100%-frees their VRAM for the seed build + training at 1200p. Each heavy model runs in its own conda env (SAM worker, AnySplat worker, in-process XFeat in the main env, plus the ROS publisher env owned by the live source). A pipe-protocol nuance: the worker's CUDA_HOME is derived from CONDA_PREFIX at import, so the launcher must pin CONDA_PREFIX to the worker env or it KeyErrors.
- VRAM scheduling is a hard 16 GB-ceiling ordering, not a speed preference. At sweep start ONLY the 3D generator is prewarmed (largest single load, given the GPU/CPU to itself so it hides under the sweep). The 2D segmenter is loaded lazily right before segmentation and released immediately after (its residency during the generator's load peak would OOM the card; holding it idle through generation wastes ~0.85 GB). The dynamic-phase models (AnySplat feedforward ~3.4 GB, XFeat) and the gsplat-backward warm are deferred until after the SAM worker is closed — AnySplat specifically cannot load concurrently with the 3D generator + Gazebo without OOMing. AnySplat's load then overlaps seed-finalize + train; the dynamic handoff waits on it.
- The dynamic-phase models are only instantiated when actually needed: a feedforward-off / static-only run never even spawns the AnySplat worker (it would never be adopted or freed).
- A throwaway gsplat rasterization + backward on a tiny synthetic scene (16 Gaussians, 64x64) is run on a daemon thread in the freed slot after the SAM worker closes, purely to force gsplat's slow backward CUDA kernels to JIT-compile (cached on disk) there instead of stalling the first real training step.

## DYNAMIC PHASE

### Static -> dynamic handoff
- The static and dynamic phases run in ONE process with NO reload: the in-memory scene (model + per-Gaussian buffers + a single model lock) is re-phased IN PLACE rather than rebuilt. WHY one process: the feedforward decoder and tracker models are warm-loaded during static and reused; a second command would kill and re-spawn them, stalling the first dynamic decode.
- Re-phasing flips three things in place: (1) dynamic LR policy = ALL Gaussian-param learning rates 0 (a backward hook also hard-zeros the position gradient so no stray optimizer step can move the seed positions; static relied on means-LR=0 instead); (2) the buffer store switches from exact-realloc to a free-list (swap-remove/insert with over-allocated capacity) for runtime cull/insert; (3) the renderer is told to rasterize only the live `[:count]` view so dead/free rows never render. This reaches the exact state a fresh dynamic-phase load would, minus the reload.
- The already-warm feedforward and tracker handles are passed straight into the dynamic driver and reused in place (scene not rebuilt, decoder not re-spawned, only a readiness wait), so the first decode is at steady-state.

### D0 object selection
- The single tracked object is chosen as the most-common NON-ZERO per-Gaussian instance id (fusion writes ids 1..K; the most-populated instance is the real fused object vs stray ids). Returns -1 if no non-zero id exists, which makes the dynamic loop fail loud at construction (a -1 selection would silently track nothing).

### Live driver: frame pull, wrap, reset
- Each loop iteration reads the NEWEST frame from the shared-memory ring (not a FIFO pop) and drops stale/duplicate frames (sleep 0.002 s and continue). WHY: real-time tracking must follow the live present, not accumulate a backlog.
- An episode wrap is detected when the capture stamp jumps BACKWARD by > 0.5 s (threshold avoids normal inter-frame jitter); on wrap the loop resets to the D0 state so every replay pass starts identically.
- Reset restores D0 by: moving the tracked object back to its rest pose (identity transform), culling every feedforward insert (rows tagged with the insert instance id 999), un-hiding any deferred-cull rows, and forcing a re-seed on the next frame (which clears the tracker's anchors, Kalman filter, and cumulative pose). The D0 reference is re-captured at the restored rest pose so it stays the original anchor.

### Per-tick input prep
- The frame is moved to GPU: RGB (BGR->RGB, /255), depth (metres, 0==invalid), and a gripper/robot keep-mask. Depth is cleaned with a median + bilateral filter by default. WHY: the tracker's RANSAC-Kabsch fits 3D points back-projected from depth, so stereo flying-pixels would corrupt the pose.
- The gripper region of the live RGB is repainted with the render background (Gazebo sky color, NOT black) before tracking: keep=1 keeps the real pixel, keep=0 paints background. WHY: otherwise keypoints lock onto the moving gripper texture and the tracker follows the gripper; a background fill (not black) avoids injecting a false edge.

### Per-tick object mask + crop
- A pixel silhouette of just the tracked object is rendered each tick by rasterizing ONLY the selected Gaussians (instance id == tracked id), thresholding rendered alpha at 0.5. The Gaussian snapshot is taken INSIDE the model lock so the mask length matches the params being rasterized (a concurrent insert can't cause a torn read). This silhouette confines the tracker to object pixels and tells the decoder which region is the object.
- By default the frame is cropped to the object's bounding box, padded by 150 px (clamped to frame, min box side 16 px). WHY: the tracker extracts a fixed budget of keypoints (top_k=1024); over a full 1200p frame they spread everywhere and a small object gets few, so cropping concentrates the budget on the object. The crop shifts only the principal point (cx,cy by the crop origin), leaving focal length unchanged, so depth back-projection stays metric and the world-frame pose is crop-invariant.

### Per-tick seed-vs-track branch
- First frame (seed): capture the D0 reference (rest-pose means/quats keyed by a STABLE per-Gaussian uid, not row position) and initialize the tracker anchor from object-masked keypoints. Returns identity, moves nothing. Seeding is gated on the tracker having enough keypoints (min 12 trackable points).
- Every later frame: estimate motion, and if successful, rigidly transform the D0 rest means/quats by (R,t) and write them onto the live rows matched by uid (resolved under the buffer lock). WHY uid-keyed: the free-list reorders rows on cull/insert, so the tracked object is keyed by stable uid, never row position — a concurrent insert between snapshot and write can't misplace the pose.

### Per-tick feedforward (FF) gating + telemetry
- FF fires only on every cadence-th tick (default 20; dataclass default 10) AND only when no prior decode is still in-flight (single decode at a time). WHY: the decode is slow and runs on a background thread; cadence throttles inserts, the in-flight guard prevents stacking decodes.
- When due, an IMMUTABLE frozen dispatch is built (sequence, dispatch-time camera pose, a COPY of the live RGB, filtered depth, object mask, gripper keep, scene intrinsics, tracked id) and handed to a daemon thread that reads ONLY this frozen snapshot. WHY immutable: it guarantees the camera pose the change-detector scores against is identical to the pose the inserts are placed against, eliminating a re-insertion loop where a scoring-vs-placement pose mismatch re-inserts the same surface every cycle; the RGB copy lets the producer overwrite the live buffer.
- Each tick emits a trace row (tick, frame seq, tracking ok, inliers, R/t, ff fired/inserted/culled, total Gaussian count) used for A/B equivalence verification, plus a timing marker proving the tracker keeps ticking lock-free during a long decode. A per-tick rigid trajectory (anchor + pose records) is optionally logged to disk.

### Tracker: extraction & matching
- Tracking uses XFeat sparse keypoints (one CNN forward producing detect+describe) with top_k=1024 keypoints, 64-D L2-normalized descriptors, detection threshold 0.05.
- Matching is anchor<->current via LighterGlue (the XFeat-author slim LightGlue, 6 transformer layers), min match confidence 0.1, requiring >= 12 keypoints per side; layer early-exit is DISABLED in sim (depth_confidence = -1.0). If LighterGlue is unavailable it falls back to mutual-nearest-neighbour matching. WHY LighterGlue over MNN: its cross-attention rejects ambiguous background<->background matches that would otherwise flood RANSAC with zero-motion matches and drown the object's motion.
- Both the D0 seed and any new anchor extract XFeat on the FULL (cropped) image, then KEEP only keypoints landing inside the object mask. WHY post-filter not pre-mask: masking the image first corrupts boundary descriptors and makes anchor descriptors inconsistent with the per-tick full-image descriptors. If fewer than 12 survive, the filter is skipped (mask probably wrong).

### Tracker: depth back-projection + RANSAC/Kabsch
- Depth is bilinearly sampled at each keypoint (a point is invalid if any of the 4 taps is non-finite or <=0) and back-projected to world in OpenGL camera convention (forward = -Z). Anchors store only depth-valid 3D points (Kabsch needs 3D).
- Pose is estimated by 3-point RANSAC over closed-form Kabsch: 68 iterations, inlier threshold 0.004 m, deterministic RNG seed. It keeps the trial with most inliers (ties broken by lower mean residual), then REFITS Kabsch on the full inlier set if >= 12 inliers. Kabsch = center both clouds, SVD, reflection-fixed rotation, translation from centroids.
- The current frame's matches are restricted to a keep region = gripper-keep INTERSECT a dilated halo (radius 80 px, 161x161 kernel) around the object's PREDICTED footprint. WHY: once the object is grasped and lifted, the crop fills with static background whose consistent zero-motion matches would outvote the object's true motion and pin the pose ("object stops moving"); the halo lags one tick, hence the dilation. If the object-masked set drops below 12 points the filter reverts to gripper-keep-only so an occluded/tiny mask can't kill tracking. The anchor side is never region-restricted.

### Tracker: multi-anchor bank
- Instead of frame-to-frame matching, the tracker keeps a POOL of keyframe anchors (anchor 0 = D0, rotation I, translation 0) and always matches anchor<->current, so drift is bounded to ONE anchor-to-current hop no matter how far the object rotated. The D0->current pose composes as T_current = T_local . T_anchor; this RAW cumulative pose (never the Kalman-smoothed output) drives anchor selection/creation, to avoid feeding smoothing lag back into tracking state.
- The nearest anchor is selected by RELATIVE (object-in-camera) rotation distance — geodesic SO(3) angle between the predicted and each anchor's object-in-camera rotation. WHY relative: that is what the matcher actually matches on (appearance from a viewpoint), so it handles camera-only, object-only, and combined motion.
- Per tick it tries at most 2 attempts (nearest then 2nd-nearest anchor), keeping whichever yields more inliers, and STOPS early once an attempt clears 20 inliers (intentionally above the 12-point success floor so the fallback fires before full pose loss).
- A NEW anchor is captured when no existing anchor covers the current view within BOTH a rotation gate of 22.5 deg AND an apparent-scale gate of 1.3x (apparent size ~ 1/camera-distance; beyond ~1.3x the matcher sheds matches). This tiles orientation x scale space (~16 anchors over a 360 deg sweep). Translation is never used in either gate.

### Tracker: success, spike gate, Kalman filter
- A tick succeeds iff RANSAC inliers >= 12; on failure the last cumulative pose is held. An optional relative spike gate (OFF by default) rejects a tick whose inliers fall below a fraction of the rolling median (over the last 30, once >= 8 samples) as a degenerate match; rejected ticks still feed the history so a SUSTAINED drop (motion onset) lowers the median within ~8 ticks and tracking resumes.
- An OPTIONAL pose Kalman filter (OFF by default; default path uses the raw cumulative pose) is a constant-velocity error-state KF on SE(3): 12-state [position, velocity, rotation-error, angular-velocity], smoothing only the (R,t) returned to the pipeline. Sigmas: accel 0.005, alpha 0.025, measurement translation 0.020 m, measurement rotation 10 deg. Lower process noise = smoother + more lag; lower measurement noise = more responsive. Measurement noise is inflated adaptively per tick by sqrt(80/inliers) clamped to 1.0..4.0, so weak match sets lean on the velocity model.
- The KF dt is the REAL elapsed gap between the two frames actually filtered, derived from the frame CAPTURE stamp (rate-invariant, correct under frame-drop), clamped to (0, 0.5) s with a 1/20 s fallback; default synthetic fps fallback is 9.0.
- Three KF innovation defenses: (1) physics reject — a per-tick translation faster than max-speed 0.4 m/s holds the predicted pose for up to 2 ticks before accepting a genuine reacquisition; (2) snap gate — an innovation past 0.05 m / 10 deg (plus a speed-scaled term, k=3.0) is treated as a discontinuity (reacquisition/anchor jump): snap nominal to the measurement and zero velocity rather than overshoot; (3) robust-R spike gate — inflate rotation covariance past 3-sigma + speed term to coast through degenerate-match spikes without lagging legit fast motion. All floors add a speed*dt term so they self-scale.

### Tracker: static-hold + quaternion
- After the KF, a static-hold collapses stationary wander: it keeps the last 15 PRE-hold outputs and, when their net translation trend < 25 mm AND net rotation trend < 10 deg, outputs the per-axis MEDIAN of the window instead. WHY: a motion-responsive filter cannot also erase few-mm/deg wander at low inlier counts; a trend-gated median can, at the cost of a small onset deadband. Output-side only; the raw cumulative pose is untouched.
- The (3,3) rotation is converted to a wxyz quaternion by branching on the largest of {trace, R00, R11, R22}. WHY: the trace-only formula degenerates for angles >= 120 deg, so picking the largest diagonal/trace term stays numerically stable for all angles. The delta-quaternion is then composed (Hamilton product) with the reference quats.

### Tracker: D0 reference (uid-keyed)
- The D0 reference clones the tracked object's rest-pose means and quats plus each row's STABLE uid (not row position), pre-sorting by uid once for fast per-tick alignment. WHY uid-keyed: the free-list reorders rows, so keying by uid lets the transformed pose always land on the right Gaussian; per-tick apply aligns reference->current rows by uid (no host sync) and bails if the uid set or count drifted. The applied pose is means @ R^T + t and a delta-quaternion times the reference quats; the final write resolves uid->live row under the model lock so a concurrent cull/insert can't misplace it.

### FF worker: in-flight guard + cleanup
- The worker runs at most ONE decode at a time via a non-blocking slot lock; on any launch failure or crash the slot is ALWAYS released in a finally so FF can never permanently wedge, and any exception is caught/printed so the daemon thread never dies silently.
- After EVERY cycle the worker empties the CUDA cache. WHY: the decoder runs in a SEPARATE process sharing the GPU; not freeing per-cycle transients starves it and causes OOM.

### FF worker: cycle order + locking
- One cycle, fixed order: render scene + score change region (skip if empty) -> compute the in-front occluder cull against the first region -> re-score the change as-if-culled (region-restricted) -> snapshot for the ICP target -> DECODE (lock-free, the long pole) -> enforce the size ceiling -> commit cull+insert.
- The shared model lock is held only for the short snapshot/hide/cull/insert ops; the decode is lock-free. This is safe because during the decode the ONLY concurrent mutation is the tracker writing pose VALUES in place (no cull/insert/reorder), and cull/insert come only from this single FF thread, so indices stay valid; the protect mask is still rebuilt fresh just before commit.

### FF worker: cull math
- In-front cull: by direct projection (no render), find eligible Gaussians floating > 10 mm IN FRONT of the live sensor surface inside the change region and delete them. Eligible = background (id 0) OR prior FF inserts (id 999); the tracked object's id is excluded (plus a belt-and-suspenders protect mask). WHY the 10 mm margin: with 0 tolerance, depth noise at a real object's silhouette deleted genuine geometry; 10 mm only removes clear floaters.
- Replaced-surface cull (default thin-slab thickness 0.0 m = effectively off): delete OLD eligible geometry the fresh insert overwrites — only in a thin slab JUST BEHIND the live surface, never the whole column behind. WHY bounded slab: deleting everything behind would cull deep walls/background and the scene would vanish; a thin behind-only slab caps growth without leaving holes.

### FF worker: atomic commit, ceiling, purge
- Default (deferred) path: the in-front cull is NOT committed before decode; those rows are VIRTUALLY hidden (opacity-zeroed) only so the re-score sees an as-if-culled scene, then un-hidden. After the decode confirms inserts exist, the in-front cull + replaced-surface cull + any due purge are folded into ONE atomic cull+insert surgery. WHY atomic: the count is written once, so no reader/render ever sees a culled-but-not-yet-filled scene (no hole/flicker); new geometry replaces old in the same step. The non-deferred path commits the cull first and can briefly show a hole, hence deferral is the default.
- Size ceiling = 2,000,000 Gaussians. When an insert would exceed it, the worker first purges weak inserts, then admits only as many new Gaussians as fit (trimming or refusing the batch). This is the load-shed guard against unbounded growth.
- Periodic purge (cadence default 0 = disabled) drops low-opacity FF inserts: eligible = rows flagged inserted AND id == 999, with activated opacity < 0.05. It structurally never touches the tracked object or static background.
- Every FF insert tags its rows with object-flag 1.0, instance id 999, inserted-flag 1.0, which makes them self-managing — eligible for both culls and the purge on later cycles, and distinct from static background (id 0) and the tracked object.

### Change detection (CDN)
- Per cycle, the current scene is rendered from the dispatch pose (the only locked step); change is scored as 1 - SSIM against the live RGB; SSIM + cleanup run lock-free. Output is a list with one region mask, or empty (FF then skips decode).
- A per-pixel VALID gate is built first: EXCLUDE the tracked object footprint (the tracker is moving it, so render-vs-live always disagrees there — counting it as change would smear new geometry onto the object), and exclude robot pixels by multiplying in the gripper-keep mask ERODED by 6 px (enlarging the exclusion zone, since the robot silhouette is imperfect). The eroded mask is CDN-only; the tracker still reads the raw keep mask.
- Validity also requires rendered coverage (alpha > 0.5) OR a live sensor depth in [0.05 m, 3.0 m]. The depth OR rescues UNCOVERED holes: a barely-covered pixel where the sensor sees a real near surface is a fillable void; a genuine void with no return stays dropped. Depth is used ONLY as a binary validity gate, never as a difference metric.
- Both images are downsampled (masked avg-pool, excluded pixels don't bleed) to ~150x150 cells regardless of resolution, lightly Gaussian-blurred (kernel 5, sigma 0.75, mask-normalized) to kill single-pixel noise, converted to luma grayscale, then scored by windowed SSIM (Gaussian window 5, sigma 1.5, c1=0.01^2, c2=0.03^2), single-scale. WHY coarse: coarse blocks make the comparison robust to sub-block tracker/render jitter and cap SSIM cost by grid size.
- The dissimilarity is thresholded at 0.2 (a low threshold paired with a SMALL close kernel so faint scattered detections aren't bridged into a solid square), AND'd with the valid mask, then cleaned: morphological close radius 2 (fills 1-2 px holes) then open radius 1 (removes single-px speckle). Tiny radii deliberately: a large close bridged noise into false squares and a large open wiped thin real edges.
- Connected components are labeled; every component >= 40 grid cells is kept (largest-only is off). The cleaned grid mask is nearest-upsampled to native and AND'd with the full-res valid mask. WHY mask AFTER SSIM, never blacking the input first: SSIM is a sliding window, so pre-blacking creates a fake edge that fires as change at the border, and it saves no compute.
- The tracked-object footprint is then hard-subtracted at native resolution (a second guarantee a patch is never decoded ONTO the object), with the footprint enlarged by scale 1.1 about its centroid to swallow the render-vs-live misplacement ring (dilate default 0). An all-empty result means no change -> FF skips.
- The re-score (after hiding the would-be-culled rows) renders ONLY the Gaussians whose means project into the first region's padded bbox (pad 50) and AND-gates the new mask to that first region. WHY: the restricted render leaves everything outside the bbox bare, which would falsely flag as change; the AND-gate discards exactly that. Consequence: the replaced-surface cull can only delete geometry inside the originally-detected region.

### Decode: crop windows + AnySplat
- The decoder is AnySplat, run as a persistent subprocess in a SIBLING conda env (its pinned wheels are incompatible with the main torch stack), 60 s timeout, lazily spawned under a lock, prewarmed on a background thread (with a dummy 448x448 forward) so the model load overlaps setup instead of stalling the first decode. IPC: one JSON line over stdin/stdout, the heavy Gaussian arrays travel as a pickled npz on tmpfs (/dev/shm) — pickle not np.savez because savez CRC32-wraps each array (costly on the large higher-order SH).
- The change-mask bbox is cropped to a SQUARE window (side = max(bw,bh) + 2*pad, pad 50, clamped to frame) since AnySplat consumes a fixed 448x448 input; if the bbox is wider than the image short side it tiles into TWO square windows, each a separate single-view inference whose outputs are concatenated. Each AnySplat forward here is MONOCULAR (one view).
- The worker returns canonical Gaussians: log-scales, logit-opacities, and SH sliced to the FIRST 16 coefficients (degree 3) split into a DC term + 15 rest, dropping AnySplat's 4th SH band (the dominant payload) before the host copy.

### Decode: reprojection to scene
- Placement IGNORES AnySplat's predicted depth/scale/focal (its focal has ~28% lateral error). Each Gaussian is projected into the predicted camera to get its pixel, mapped back to the true scene pixel (exact inverse of the square crop+resize), and BACK-PROJECTED through the SCENE intrinsics at the LIVE sensor depth at that pixel — so inserts are pinned on the true surface. Orientation is rebased from AnySplat's OpenCV canonical frame into the scene's OpenGL basis (diag(1,-1,-1) axis flip) so splats don't render mirrored.
- Because each splat is moved to sensor depth instead of its canonical depth, its scale is multiplied by (sensor_depth / canonical_depth) in log-space, so a splat moved twice as far doubles its size to keep the same pixel footprint.
- One combined keep mask drops splats by: opacity (sigmoid >= 0.05); background color (decoded color within 0.08 per-channel of the Gazebo sky 0.86/0.92/1.0, killing sky splats); the CDN change mask (pixel must land inside it); and in-image (front, inside 448).
- Before decode, the scene camera pose is refined by GPU point-to-plane ICP of the live depth cloud against a downsampled projection of the scene's FRONT-surface Gaussians (per stride-4 pixel cell, keep the camera-nearest Gaussian, like a depth sensor): 30 iters, 0.02 m max correspondence distance, min 1000 points; the result left-multiplies the pose. Failure is caught and decode continues with the raw pose. (ON by default.)

### Decode: density shaping
- The concatenated insert is randomly subsampled if over 80,000 points (the corner-detection kNN spikes on a large revealed region; shaping is cosmetic flat-fill).
- Each point gets a [0,1] cornerness = max of (1) a PCA surface-variation CREASE term (normalized by 0.10) and (2) a BOUNDARY term = neighbour-centroid offset / mean neighbour distance (normalized by 3.0), over an 80-neighbour kNN; corner if score >= 0.13. The corner set is then grown by ONE neighbour hop (any of the 50 nearest neighbours is a corner), computed on the original mask so there's no cascade. The boundary term catches flat silhouette patches the crease metric is blind to.
- Points split into FLATS (~corner) and CORNERS. Flats are voxel-merged at 1 mm then grown in-plane by 2.0x; corners are kept RAW. WHY: a 1 mm voxel straddling an edge would fuse two surfaces into one splat poking past the corner, and growing an edge splat fills the void behind it. In-plane growth adds log(factor) to the two larger axes (skipping the smallest = surface-normal axis) so the footprint grows without thickening the surface.
- Voxel-merge fuses each multi-point voxel into ONE Gaussian: opacity-weighted mean position/color; covariance = mean member covariance PLUS the spread of member means about the cluster mean (the EXTENT term that sizes the merged splat to fill the voxel); merged opacity = cluster MAX (preserve coverage).
- A final UNIFORM scale clamp: any Gaussian whose largest axis exceeds 2 cm (max_scale_m=0.02) is uniformly shrunk on all three log-axes so the biggest axis becomes exactly the cap and the splat SHAPE is preserved (not a per-axis clamp that flattens it, not a cull). The output is the new Gaussians for the changed region, which the FF worker then inserts.

### Viewer + recorded verification
- Live and view drivers render via the SAME single model lock that guards every tracker pose-write and every FF insert/cull. WHY: a render reads the params while the tracker/FF mutate them; without the shared lock a render could rasterize a half-applied pose or a torn insert. The viewer is server-side rasterize + push-image on port 8081; the Nerfstudio viewer is never used.
- A headless, frame-exact recorded driver (FF off by default) ticks deterministically so the new pipeline's per-tick R/t/insert/cull counts can be diffed against the frozen old pipeline's trace for functional-equivalence verification.

## SHARED FOUNDATIONS

### Sim sensor source & camera intrinsics

- Inputs that become one sensor frame come from ROS sim topics: JPEG-compressed RGB, raw depth, camera intrinsics, robot joint states, and the ground-truth Gazebo camera world pose. The publisher runs in a minimal ROS Python-3.8 env (no torch), so the mask-render module is the single source of truth for topics, intrinsics, and mask logic, shared between publisher and pipeline.
- Intrinsics (fx, fy, cx, cy, width, height) are taken from the CameraInfo message. Gazebo only publishes camera_info while the image stream has a subscriber, so a primer subscriber is held while polling for camera_info in <=2 s slices up to a 20 s deadline; on success it is cached to disk, on timeout it falls back to a recorded dataset's transforms file or the cache.
- Depth is subscribed RAW, not via compressed-depth transport, because the compressed transport uses inverse-depth log encoding that a naive uint16-mm decoder misreads ~32x too large and destroys downstream pose fits. 32FC1 is read as float32 metres directly; 16UC1 is multiplied by 1e-3 to metres. Gazebo emits 32FC1 metres.
- RGB arrives JPEG-compressed (~50 KB vs 1.9 MB raw) and is decoded to BGR uint8 via libjpeg-turbo (falling back to OpenCV).
- RGB and depth are paired by an approximate-time synchronizer with queue size 20 and slop 0.02 s. Slop is tightened from the default 0.1 s to 0.02 s because Gazebo co-stamps RGB and depth within microseconds; a large slop forces a per-match pivot-wait of ~slop and caps throughput.

### Sim-to-real depth noise (synthetic ZED model)

- Sim depth is essentially noise-free, so a synthetic ZED-X noise model is applied to close the sim-to-real gap (ON for sim by default, OFF for real). Per-pixel axial Gaussian noise with std sigma_z(z) = sigma0 + k*z^2, where sigma0 = 0.00147 m (1.47 mm flat term) and k = 0.000500 m/m^2 (fit to a real ZED scene's p90 upper bound), added only to valid (>0) pixels.
- A range gate nulls depth outside [0.05, 3.0] m (matching the fusion depth window), and a 1% random hole rate (0.01) zeroes that fraction of still-valid pixels.

### Camera pose in sim

- In sim the camera pose is NOT from FK; it uses the Gazebo ground-truth pose plus one static URDF-FK link offset (camera body frame to optical frame). For an image stamp with no exact pose sample, the bracketing poses are interpolated: SLERP on the quaternions, linear on the translation.
- The optical pose is converted from ROS optical convention (+X right, +Y down, +Z forward) to nerfstudio/OpenGL (+X right, +Y up, +Z back) by right-multiplying the 3x3 rotation by diag(1, -1, -1); translation is preserved. This conversion is applied to every pose written to SHM and to saved transforms files.
- Joint and pose buffers are kept time-sorted, throttled to drop samples within 0.02 s of the last (50 Hz storage is enough to bracket ~33 ms image stamps).

### Robot self-masking (keep-mask render)

- A "keep mask" excludes robot/gripper pixels from the scene. It is rendered offscreen with pyrender from the arm+gripper URDF: each link's visual meshes/primitives are posed by the link's FK at the frame's joint angles, and only the depth buffer is used — keep (255) where nothing was drawn, robot (0) where the robot occupies pixels. Material color is irrelevant.
- The mask is posed from the camera link's FK, not the Gazebo pose topic, so its convention needs extra body-to-optical remaps before the optical-to-OpenGL flip.
- Joint angles for the render are sampled at the image stamp, interpolating linearly between bracketing joint samples; an out-of-buffer query returns the boundary sample and warns that the camera pose may be frozen.
- The mask is rendered at a fraction of full resolution (default scale 0.25, clamped to [0.1, 1.0]) then NEAREST-upscaled to full res — the silhouette is coarse so this is visually identical while cutting fill cost. Render near/far planes are 0.001 m / 100 m. Set scale to 1.0 for full res.
- The robot region can be grown by N px (default 0 in sim, 16 on real hardware) to cover silhouette under-coverage. The grow is OUTER-ONLY: a plain erosion would also fill the gripper's concave jaw gap and hide a grasped object, so eaten pixels that are NOT reachable from the image border (enclosed interior, e.g. the jaw gap) are restored — outer silhouette grows, concavities stay open.
- The on-disk recorder path additionally erodes the keep region by 4 px (kernel 9) and drops keep connected-components smaller than 64 px; background-color masking exists but is disabled (only the robot is excluded).
- During the same FK pass, each gripper inner-finger-pad distal tip world point is computed (tip = link origin + R_world @ [0, 0, 0.0375/2], half the 0.0375 m pad length along local +Z) and stored alongside the mask for a viewer overlay, perfectly synced to the rendered pose at zero extra FK cost.

### Frame-render overlap & freshness

- The sync callback only enqueues messages into a bounded drop-oldest queue (maxsize 4) so the socket always drains and the freshest frame is kept. A worker thread does pose interp + decode + noise + mask + SHM write; a separate thread owns the GL context and renders one mask per request.
- The worker submits a mask request FIRST, then decodes RGB/depth concurrently, then waits (timeout 1.0 s) — so frame time is max(mask, decode), not their sum. Each request carries a monotone sequence id; a result tagged with a stale id is rejected and the frame dropped, preventing a slow render from being consumed for the wrong (newer) frame and permanently desyncing mask vs RGB/depth.

### Keyframe selection & disk recording (static dataset)

- During disk recording the static dataset is de-duplicated by greedy ORB-SLAM-style motion keyframing: a new camera pose is accepted only if, versus EVERY kept frame, it exceeds at least one threshold — translation > 0.02 m OR rotation > 20 deg (rejected only if some kept frame is within BOTH). This avoids flooding the static set with near-duplicate views while an operator sweeps the camera by hand.
- Accepted keyframes are written as BGR PNG (RGB), uint16-mm TIFF (depth), and PNG keep-mask, with a per-frame atomically-rebuilt transforms file holding intrinsics + OpenGL c2w per frame.
- If depth filtering is on, raw depth is saved separately and a filtered depth is written: median (kernel 5) then bilateral (diameter 5, sigma_color 0.01 m = 1 cm, sigma_space 5.0), validity-mask-normalized so zeros never bleed into valid pixels.

### Static seed point cloud

- Recorded keyframes are back-projected into one world-frame point cloud (the geometry seed the static Gaussian fit locks positions onto), capped at 600000 points distributed evenly across frames by valid-pixel count. Back-projection uses the OpenGL camera convention (x = (u-cx)z/fx, y = -(v-cy)z/fy, z negated) then the frame's OpenGL c2w to world; colors converted BGR to RGB.

### Throttling (publisher contention relief)

- Output-rate cap (off by default): drops frames before the heavy worker path if within 1/max_hz of the last kept frame; used only for the static-sweep publisher.
- RGB-only latch: once the static pipeline signals via a sentinel file, the worker decodes only RGB for the viewer feed, writes zero depth and a full-keep mask (skipping the GL mask render and depth decode), and caps output to ~10 Hz — freeing the GPU for the concurrent seed build + static train. The sentinel lives in the live root (wiped per spawn) so the dynamic publisher never inherits it.

### Frame data unit

- The sensor unit is a frozen RGB-D-mask-pose tuple in the producer's CPU/numpy domain: seq (monotone, starts at 1), stamp_sec (capture event-time, never wall-now), rgb_bgr (uint8 BGR), depth_m (float32 METRES, 0 = invalid), mask_keep (uint8 {0,1}, 1 = keep), c2w_4x4 (float64 OpenGL camera-to-world), plus two optional gripper-pad world points (zeros = not available; viewer skips a marker at world origin).
- Depth is float32 metres at this boundary (not uint16-mm), so every downstream consumer is unit-agnostic; the uint16-mm form is internal to the recorded-replay loader only.
- The camera model (width, height, fx, fy, cx, cy) is a frozen per-segment contract written once into the SHM header and re-derived on attach by every reader, so consumers never hardcode resolution or focal length.

### SHM ring transport

- Transport is a shared-memory ring of 4 slots — drop-oldest / latest-wins, NOT a queue: a frame is written into slot (seq mod 4) and the consumer always reads only the freshest slot. No backpressure; a slow consumer simply misses intermediate frames, mirroring live behaviour. The slot count is propagated in the header so both sides agree on the modulus.
- A fixed little-endian header carries a 4-byte magic tag, a layout version, intrinsics, slot count, latest_seq, and ready/shutdown flags. On attach a mismatched magic or version raises immediately, so producer/consumer schema drift fails loudly instead of reading garbage.
- Each slot has a small meta block (seq, stamp, flattened c2w, two finger world points) preceding the image payload (RGB then depth then mask, contiguous). Pose/marker data lives in the cheap meta block, not the image payload, so it can be read separately. All views are zero-copy aliases over the shared buffer.
- Writes use a single-writer lock-free seqlock: tag the slot's leading seq, fill the payload, then publish by writing header latest_seq LAST (release barrier). Reads (up to 5 retries) re-read the slot seq before and after copying out; a mismatch means the writer lapped mid-read, so the read retries. The double-check is the torn-read / validity test. The reader copies arrays out so the returned frame owns its data.
- The producer unlinks any leaked stale segment of the same name BEFORE creating a fresh one (crash recovery), then sets ready. The read-only consumer NEVER unlinks and de-registers itself from the resource tracker so it can never reclaim a segment it didn't create (works around a CPython resource-tracker over-unlink bug). Shutdown only sets a header flag (a reader may still be mid-read) and relies on process exit to release memory.
- The producer side is stdlib + numpy only (no torch/rospy), so it is importable from the minimal Python-3.8 ROS env.

### Source abstraction (live vs replay are identical downstream)

- A single factory opens one of three frame sources into the SAME SHM ring, making live and recorded paths identical to everything downstream: the recommended live source spawns the proven Python-3.8 ROS publisher and tells it to write the pipeline's SHM segment DIRECTLY (no forwarder thread, no intermediate copy), an alternate live source runs the publisher in the dedicated ROS conda env in its own session, and the replay source drives a recorded dataset.
- The replay source drives a recorded dynamic dataset "as if live." Frames are sorted by the last integer in each file path so numeric capture order is preserved regardless of zero-padding. In PACED mode (default) a daemon thread writes every frame on its capture-stamp schedule so the consumer naturally trails/drops like live (an honest real-time proxy); the pacing timeline uses real stamps when present, else a synthesized uniform cadence (default 15 fps, also forceable). In FAST mode there is no thread and the harness pulls one frame per step (lock-step, frame-exact, deterministic — used for the pose A/B comparison).
- The replay loader reads RGB as BGR uint8, depth UNCHANGED and converted to metres via a 1e-3 factor (the load-bearing uint16-mm to float32-m conversion), and mask binarized as (m>0) defaulting to all-keep when absent.
- A live source's close sends SIGTERM directly to the publisher (whose own handler drops the ROS node and unlinks the SHM) rather than killing the whole process group, because the publisher shares the parent's process group and group-kill would take the parent down too.

### Camera build & geometry convention

- One nerfstudio camera is built per frame straight from the OpenGL c2w (top 3x4) plus raw intrinsics, PERSPECTIVE. No diag(1,-1,-1,1) flip is applied at this layer; the OpenGL-to-OpenCV handedness is consumed downstream where the projection math negates z and y.
- The transport layer does NO recentering, rescaling, or orientation change: poses are metric and the c2w is forwarded verbatim. The SHM unit is convention-faithful but convention-neutral.

### Configuration system & conventions

- One module is the SINGLE place environment variables are read; every other component receives a frozen, immutable sub-config (no lock needed across the three threads). A missing var falls back to the dataclass default; a boolean env enables on ANY value other than the literal "0".
- World convention: poses are metric and NOT recentered/rescaled — the live-sim path uses no nerfstudio dataparser; the camera is built directly from the frame's OpenGL c2w, so orientation/center/scale are identity by construction.
- Module step counts: static train 500 steps, recorded-dynamic 5000 steps, live-dynamic effectively unbounded (~1e6).
- Root config defaults: source "sim" (sim enables depth noise, real disables it), resolution 1920x1200, background color (0.86, 0.92, 1.0) (Gazebo sky, hard-validated — changing it raises).

### Tracker (rigid pose tracking)

- The tracker estimates the object's rigid transform per tick using XFeat features + LighterGlue matching, with a RANSAC pose fit. Key params: top_k = 1024 features, ransac_iterations = 68 (higher = stabler inlier consensus), ransac_inlier_threshold = 0.004 m (lower = stricter), crop to object bbox with 150 px padding, object-mask filtering on, min_track_points = 12.
- Gates reject bad fits: rotation_gate_deg = 22.5, scale_gate_ratio = 1.3 (scale-select off).
- A stillness gate marks the object static (killing steady-state shake) if motion over the last 15 ticks stays under 25 mm AND 10 deg.

### Pose filter (Kalman, default OFF)

- A constant-acceleration pose Kalman filter, DEFAULT OFF so the deterministic A/B matches the old pipeline. It feeds event-time dt (never wall-clock) at a nominal 9 fps, making it rate-invariant. Process noise: accel_sigma 0.005, alpha_sigma 0.025. Measurement noise: 20.0 mm translation, 10.0 deg rotation. An innovation snap-gate (0.05 m / 10 deg) treats a larger jump as a reacquisition and SNAPS to the measurement rather than smoothing through it.

### Change detection (per-frame moved-region mask)

- Change detection runs on a DOWNSAMPLED grid (longest side 150 px) using SSIM: rgb_threshold 0.2 is the 1-SSIM dissimilarity cutoff, with a Gaussian pre-blur (sigma 0.75, kernel 5) and a small single-scale SSIM window of 5 to keep detection tight on the small grid.
- Post-processing: keep any pooled block with a valid pixel, drop change blobs smaller than 40 grid-cells, morphological close 2 px (fill small interior holes), open 1 px (remove single-px speckle), scene-coverage threshold 0.5.
- For the feedforward path ONLY, the gripper EXCLUSION is enlarged by eroding the keep-mask 6 full-res px so the gripper silhouette never leaks into the change region (the tracker reads the raw mask). Live depth window 0.05–3.0 m.

### Feedforward inserts (AnySplat decode)

- The feedforward step fires an AnySplat decode every N tracker ticks (cadence 20 — fires AnySplat less so it does not starve the render), reconstructing new Gaussians for the changed/revealed region. Optional ICP refinement (on) aligns the inserted cloud, with a 4-px stride for both ICP clouds.
- Insert hygiene: opacity keep floor 0.05, per-axis max scale 0.02 m (uniform-shrink gross blobs), min-scale cull off (0.0), per-voxel moment-match merge at 0.001 m, and a subsample ceiling of 80000 points feeding the O(N^2) corner-kNN.
- Occlusion culls (committed with the insert): delete a Gaussian only if it sits >0.01 m (10 mm) in front of the live surface; a second cull of the overwritten old slab is on but its slab-thickness tolerance is 0 (off).
- After voxel-merge, the two in-plane (surface) axes are grown by 2.0x (normal axis untouched) to fill sub-splat surface holes without blur. The grow is CORNERNESS-GATED by a kNN-PCA score so it tapers to no-grow at edges/creases and does not leak past silhouettes: corner_knn_k = 80, surface-variation scale 0.10 (maps to a crease), boundary scale 3.0 (maps to a silhouette boundary; large enough that gently curved surfaces are not mistaken for edges), one-hop halo over the 50 nearest neighbours, and a merge threshold 0.13 — points scoring >= 0.13 are CORNERS passed through raw (keep geometry), flatter points are downsampled and hole-filled.

### Gaussian budget & purge

- Total live Gaussian ceiling 2000000 (frozen at boot). Dynamic periodic FF-purge is OFF (every-N = 0; would-drop opacity floor 0.05). Static one-shot opacity purge threshold 0.05. A static scale-clamp runs every 10 steps: any Gaussian whose axis exceeds 0.05 m is reset to 0.01 m (reset must stay below the clamp max so it cannot immediately re-trip).

### Depth filter & TSDF fusion (seed)

- Depth filter (default on): median (kernel 5, kills stereo flying-pixels) then bilateral (sigma_color 0.01 m, OpenCV-auto diameter). Valid depth window 0.05–2.0 m; the scene/loss depth max MUST equal the depth max (a loss-mask invariant — divergence raises).
- TSDF fusion builds the seed with a near voxel size of 0.002 m and a coarser far voxel of 0.01 m past a 1.0 m near/far boundary, an 8 mm truncation band, and deferred integration in the live path.

### Segmentation

- Segmentation backend defaults to FastSAM (2D segmenter), with an empty text prompt by default. Fast-SAM3D weights are trimmed by default to save VRAM. Point-cloud registration uses a non-rigid deformable-point method. Near-surface object gating: max object slope 70.0 deg, window fraction 0.012.

### Viser & static-train control

- Live visualization runs on a viser-direct server at port 8081 (the nerfstudio viewer port 7007 is never used).
- Static training runs up to 500 steps with early stop: stop when loss drops below 0.02, requiring 8 consecutive ticks under threshold, never before a 100-step floor.

### Config guards & runtime reload

- Validation runs after every config load and raises on: an invalid source value; scene-depth-max not equal to depth-max (loss-mask invariant); a static scale-reset value not below the clamp max; a real source with sim depth-noise still enabled (would double-noise real depth); or a background color other than the Gazebo sky. These make a misconfigured boot fail loudly.
- Almost all config is frozen at boot; only a small whitelist can be re-read at runtime for live A/B tuning: the FF ICP toggle, FF max/min scale, the three stillness-gate thresholds, and the two Kalman process-noise sigmas. A reload builds a NEW frozen config, re-validates, and is swapped in atomically so the three threads always see an immutable object.

### Background color enforcement & phase LR gates

- The render background is forced to the fixed Gazebo sky (0.86, 0.92, 1.0) even during training, overriding Splatfacto's default "random" composite background — which would otherwise train the static scene against a fluctuating photometric bias and make the renderer compensate with opacity tweaks at silhouettes. Empty/region-restricted renders fill with the same color.
- Phase LR gates are enforced: in STATIC, only the means learning rate is forced to 0 (positions locked on the TSDF seed; the other five Gaussian params still train); in DYNAMIC, ALL six Gaussian-param learning rates are forced to 0 because the dynamic phase is a runtime, not a training loop — only the tracker's rigid transform and FF inserts mutate the scene. In the dynamic phase a backward hook additionally zeroes any means gradient as a belt-and-braces guard. Both gates are re-asserted after any count/identity surgery.

### Persistence & warm-cache

- Persistence goes through the per-Gaussian scene representation (the SSOT), not the nerfstudio model state. Persisted: the 6 Gaussian params (means, features_dc, features_rest, scales, quats, opacities) plus 4 fixed-order identity buffers (object_flags, sam3d_init_target_flags, object_instance_ids, inserted_flags). Only the live rows are exported (dead over-allocated capacity rows are never persisted).
- The warm cache is a torch blob holding the param+buffer state, the live point count, a config fingerprint, and a layout tag. The seed point cloud is kept as a separate sibling file. The state layout deliberately mirrors the old package's so old viewers can still read it.
- Loading warns-but-does-not-fail on config drift: a fingerprint mismatch prints a drift warning and loads anyway (geometry intact, tuning differs); a missing fingerprint is accepted as legacy. The load reallocates the params at the stored count, rebuilds the buffers (zero-filling any absent in legacy caches), regenerates per-row stable ids, and re-asserts invariants.
- The warm-restart path seeds the inner Splatfacto model at the right point count and scale by decoding per-point DC color from SH band-0 to rgb (rgb = features_dc * 0.28209479177387814 + 0.5, clamped), attaches a shared render lock, and for the dynamic phase enables an over-allocated free-list so dead capacity rows never rasterize — safe ONLY because the dynamic phase has LR=0 and renders under no_grad.
- The config fingerprint is the first 16 hex chars of a sha256 over a sorted JSON dump of the whole config, so it is order-independent and detects drift between geometry built under different constants.
