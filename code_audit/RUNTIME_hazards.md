# RUNTIME hazards — prioritized + deduped (live dynamic-gs path)

Merged across 5 runtime traces (shm→batch, tracker-tick, ff-dispatch, viser-push, state-mutation-map, warmload-lifecycle). Each item: `SEVERITY/KIND — file:line (thread) — hazard — FIX — DECISION`.

Ordering: races first, then lock/lifecycle/leak, then everything else. Severity within each group.

## THE 3 MOST DANGEROUS LIVE-MODE HAZARDS (do these first)

1. **H-CROP (HIGH/race)** — `_object_crop_bbox` reads `model.means` + `object_instance_ids` on the MAIN tracker thread EVERY tick with no lock, while the FF bg thread reassigns `means` and resizes `object_instance_ids` in *separate* statements under the lock. The `means.shape == ids.shape` guard does NOT close the interleave window → `IndexError`/CUDA index-assert. This is the only main-thread hot-path read that can hard-crash the live run.
2. **H-PICK (HIGH/race)** — `_pick_d0_object` reads `model.means`/`object_instance_ids` unlocked. Safe TODAY only because the `is_first` FF gate (`base:950-951`) blocks FF during D0; a mid-run picker reseed while a prior FF drains would tear (N mismatch). The gate is load-bearing — the purge must not remove it.
3. **H-SLOTLEAK (MED/lock)** — `_anysplat_slot_lock` acquired then `Thread.start()` called; release lives only in the bg thread's `finally`. If `start()` raises (OS thread exhaustion), the slot is never released → FF silently dies for the rest of the run AND `_cleanup_anysplat_bg` blocks ~60 s at exit. One-line try/except fix.
